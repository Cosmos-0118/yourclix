## Web Research Summary (Best Methods)

### 1) Homebrew command semantics should drive remediation mapping
Source: https://docs.brew.sh/Manpage
- `brew outdated` lists packages with newer versions.
- `brew upgrade` performs upgrades of outdated formulae/casks.
- `brew cleanup` removes stale downloads and old versions; it is not the primary outdated-remediation command.
- `brew doctor` diagnoses potential problems and can return non-zero on findings; it is diagnostic, not necessarily a fix.

**Implication for `your fix`:** `brew-outdated` remediation should execute `upgrade` (or `brew optimize` pipeline), not just `cleanup + doctor`.

### 2) Dry-run/plan output should be explicit and trustworthy
Sources:
- https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_checkmode.html
- https://developer.hashicorp.com/terraform/cli/commands/plan

Key patterns:
- Separate plan/speculative output from apply.
- Show what would change and where.
- Use meaningful exit codes to distinguish: no changes, changes, errors.

**Implication for `your fix`:** add a plan report and deterministic exit-code model.

### 3) Symbolic link operations should be scope-bounded and deletion-safe
Source: https://www.gnu.org/software/findutils/manual/html_node/find_html/Symbolic-Links.html
- Symlink handling modes differ (`-P`, `-H`, `-L`), and operations affecting links can become confusing if targets change while operating.

**Implication for `your fix`:** keep remediation scope tightly bounded and avoid broad link deletion outside diagnosed roots.
